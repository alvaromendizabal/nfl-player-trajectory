# Standing execution and feature-research requirements

Owner instructions reaffirmed 10 September 2026. Apply to all subsequent work.

Work through research → hypothesis → implementation → tests → bounded experiment
→ inspection → decision → durable checkpoint → report → next milestone. Diagnose
failed and underperforming work before launching another substantial experiment.
No indefinite runs, repeated unchanged failures, or erased successful computation.

Feature engineering remains open until evidence covers the major plausible,
high-value avenues. Use NFL mechanisms, relevant primary literature, leading
solutions, statistical methods, modern temporal and player-interaction models,
and permitted historical data. Candidate count is not evidence of quality.
Each important family needs rationale, inference-time availability, explicit
leakage tests, training-only screening, matched attribution, family ablation and
chronological stability. Do not claim across-season stability from one season.

Before expensive compute verify schemas, input/source artifacts, smoke behavior,
resumability and an independently read-back durable checkpoint. Freeze a concrete
question, budget, continuation/stop thresholds, rows and comparison. Use smoke →
sample → single fold → representative validation → full experiment only as gates
justify expansion. Log UTC timestamps, elapsed time, heartbeats and counters.
Persist each completed fit before starting the next. Stop failed saves and
unproductive directions; do not continue because costs were already incurred.

After each meaningful milestone report: attempted work, completed work, passed
checks, failures, actual metric, durable artifacts, GitHub state, conclusion,
next highest-value step and why its expected information justifies compute.
Activity alone is not progress. Distinguish historical, locally verified, remotely
saved, reproducible, internal-validation and Kaggle results.

The research target is approximately 0.46 coordinate RMSE, pursuing the strongest
realistically achievable performance without guaranteeing a leaderboard record.
Maintain canonical executed notebooks, interpretable polished results, tests,
documented commits/PRs and employer-facing code quality. A 9.9/10 standard is an
objective, not a self-awarded rating while evidence or artifacts are missing.

The owner authorizes necessary ongoing project work within available connected
permissions. Continue without repetitive confirmation. Ask only at an actual
renewed-service-authorization boundary. Honor specific limits on cost, data
disclosure and submissions. These instructions do not require another user
message to complete a bounded, already authorized milestone.
